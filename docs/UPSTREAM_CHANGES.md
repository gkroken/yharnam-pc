# Changes to upstream yharnam-pc files

The `plugins` branch keeps its own code in new files. This list covers every change it makes
to a file that came from upstream (Jgamrot/yharnam-pc), so each rebase knows what to carry over
and what to look at. New files (plugin host, header, tests) aren't listed here.

| File | Change | Why |
|---|---|---|
| `src/engine_features.c` | `bb_engine_install` calls `bb_plugins_install()` after the port's own features, before the main-frame tick goes in. | Plugins load while hooks are still open (before `bb_hooks_seal`). |
| `src/engine_hooks.c`, `.h` | Adds `bb_image_size()`, `bb_hooks_sealed()`, `bb_image_code()`, `bb_image_is_code()` and `bb_hook_code()`. Every hook and `bb_patch` records the range it rewrote (`bb_image_rewritten`, queried with `bb_image_is_rewritten`). Adds `bb_hooks_set_tcb_displacement()` and `bb_hook_fix_tcb()`. | The plugin host's address checks; `write()` keeps out of code; stub space for plugin hooks (`plugin_hooks.c`); a plugin hook over the port's own rewritten bytes is refused. |
| `src/probe.c` | Before `bb_engine_install`, reports each executable segment with `bb_image_code()`, the TCB displacement with `bb_hooks_set_tcb_displacement()`, and the overlay's text entry points with `bb_plugins_set_text()`. | So `write()` knows where code is, whatever the pages' protection (all RW until after the seal, and RWX in co-op). Plugin hook stubs copy prologues before `patch_tcb_loads` runs, so they rewrite their copies' `gs:[0]` loads themselves. |
| `gpu/CMakeLists.txt` | `bb-probe` builds `src/plugin_host.c`, `src/plugin_hooks.c` and `src/plugin_game.c` and `src/plugin_params.c` with `include/`. Adds `plugin-host-test` (ten test plugins, three hook test plugins), `game-state-test`, `flag-delivery-test` (three flag plugins) and `params-test`. | |
| `gpu/bbgpu.h`, `gpu/shim/bbport_overlay.cpp` | Declares `bbgpu_plugin_message` and `bbgpu_plugin_text` (in the new `shim/bbport_plugin_text.cpp`). The overlay draws plugin text and counts it as visible. | `show_message` and `show_text` for plugins. |
| `run.py` | Sets `BB_EBOOT_109` (the community patches' 1.09 test) and `BB_EBOOT_SHA256` (of `eboot.elf`). After the mods merge, runs `scripts/paramdefs.py` (optional) and sets `BB_PARAMDEFS`. | `eboot_is_109()` and `eboot_sha256()`; param field names for plugins. |
| `scripts/mods.py` | `is_mod()`, `has_scripts()`, `has_edits()` and `own_folders()`: a folder with `scripts/*.lua` or `edits/event/*.emevd.edit.toml` at its top is a mod even with no game files (`discover`, `unrecognized`, an empty `mod_files`), and `content_root` doesn't count those folders as wrappers. `problem()` says where Lua scripts go. `main()` adds `script_edits_layer()` (with `resolved()`) on top of the layers when mods are on, and clears `out/script_edits` each start. | bb_lua loads `<mod>/scripts/*.lua`; without this a Lua-only mod was "not loaded: no game files" in the launcher, which couldn't turn it off or order it. Mods' event edits (`scripts/script_edits.py`) apply over the file mods, in mod order. |
| `scripts/emevd.py` | `append_event()`: adds an event that nothing starts; `append_initialized_event()` now uses it after its `InitializeEvent`. | Event edits with `run = false` (an event another event starts). |
| `.gitignore` | `/plugins/*.dll`. | Plugins dropped into a source tree. |
| `tests/test_probe.py` | `EXE` is `out/bb-probe.exe` on Windows. | The loader tests skipped on Windows because the file has an `.exe` suffix there. 13 of 14 now run and pass; `test_illegal_instruction_reports_guest_offset` expects a POSIX signal code. |
